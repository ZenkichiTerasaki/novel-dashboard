# レビュー・設計フィードバック

## 1. `eventType: "text"` でのキャラ立ち絵設定について（7ポジション・スロット方式のレビュー）

### 1.1 「7ポジション制 × 最大4キャラ同時表示」の評価
- **評価**: ⭕ **ノベルゲームの画面設計として非常に理にかなった仕様です**
- **理由**:
  - 横方向を7つのスロット（`pos1` 〜 `pos7`、中央が `pos4`）に分けることで、奇数人・偶数人のどちらでも複雑な座標計算なしに左右対称の美しいレイアウトが作れます。
    - **1人表示（奇数）**: `pos4`（中央）
    - **2人表示（偶数）**: `pos2`, `pos6`（または `pos3`, `pos5`）
    - **3人表示（奇数）**: `pos2`, `pos4`, `pos6`（左・中・右）
    - **4人表示（偶数・最大）**: `pos1`, `pos3`, `pos5`, `pos7`（等間隔4並び）

### 1.2 「ポジションを変数（キー）として画像を埋め込む方式」の評価
- **評価**: ⭕ **状態維持・上書き・消去の実装が最もシンプルになるため大賛成です**
- **理由**:
  - 「キャラクター名」をキーにすると、同じキャラが別ポジションに移動した際の消去処理や重複管理が複雑になりますが、**「ポジション（`pos1`〜`pos7`）をキーにして画像名（または `"none"`）を持たせる方式」** であれば、タイムラインの遡及計算が単純なオブジェクトの上書きだけで完結します。
  - さらに、毎回7ポジションすべてを保存するのではなく、**「そのイベントで変化があるポジションだけを指定する（差分指定）」** 形にするとデータも最小限になります。

#### 推奨データ構造 (`frontend/types/index.ts`)
```ts
// 左端(pos1) 〜 中央(pos4) 〜 右端(pos7) の7ポジション
export type CharacterSlot = "pos1" | "pos2" | "pos3" | "pos4" | "pos5" | "pos6" | "pos7";

export type EventDataMap = {
  text: {
    speaker?: string;
    text: string;
    // 変更があるポジションのみ指定（未指定のポジションは前のイベントの状態を維持）
    // 例: { pos4: "heroine_smile.png" }
    // 例: { pos2: "friend_normal.png", pos4: "none" }
    positions?: Partial<Record<CharacterSlot, string>>;
  };
  // ...
};
```

#### プレビュー画面（`GamePreview.tsx`）での状態計算イメージ
```ts
const activePositions: Partial<Record<CharacterSlot, string>> = {};

for (let i = 0; i <= safeIndex && i < events.length; i++) {
  const ev = events[i];
  if (ev.eventType === "text" && ev.data?.positions) {
    for (const [slot, image] of Object.entries(ev.data.positions) as [CharacterSlot, string][]) {
      if (!image) continue; // 空なら前の状態を維持
      if (image === "none") {
        delete activePositions[slot]; // "none" でそのポジションから退場
      } else {
        activePositions[slot] = image; // 画像変更（表情差分や別キャラへの入れ替え）
      }
    }
  }
}
```

### 1.3 実装前に決めておくと良い補足ポイント（3点）
1. **フォーム（`EventForm` / `EventEditModal`）での入力UIの工夫**
   - セリフ入力のたびに `pos1`〜`pos7` の7つの入力欄が常に並んでいると画面が縦に間延びするため、以下のいずれかのUIがおすすめです：
     - **案A（横並びスロット選択UI）**: `[1] [2] [3] [4:中央] [5] [6] [7]` の7つのミニボタンを横一列に並べ、クリックしたスロットだけ画像名（または `none` ボタン）を入力できるようにする。
     - **案B（行追加UI）**: `[ポジション選択プルダウン (pos1〜pos7)]` ＋ `[画像パス / none]` の行を、変更したい分だけ「＋立ち絵変更を追加」で増やせるようにする。
2. **最大4キャラ制限の扱い**
   - 1つのイベント内、またはタイムライン累積で5か所以上に同時に画像がセットされた場合、フォームまたはプレビュー上で「同時表示は最大4キャラまでです」と警告を出す（または先頭4枠のみ描画する）ルールにしておくと安全です。
3. **場面転換時の一括クリア（任意）**
   - シーンが変わる際、4人分のポジションすべてに手動で `none` を入力するのは手間がかかるため、`text` イベント（または `bg_change` イベント）に「全ポジションをクリア (`clearAll?: boolean`)」または `positions` 内で一括退場できるショートカットを用意しておくと執筆がさらに快適になります。

## 2. プレビュー画面での実画像表示（ディレクトリ構成・AWS移行考慮）
- **評価**: ⭕ **初期段階で「相対パス（キー）保存 ＋ ベースURL結合」に統一すべき**
- **レビュー内容**:
  - **最重要原則**: DB（`Event.data`）には `http://localhost:3000/...` のようなフルURLを保存せず、**`projects/1/characters/heroine_smile.png` や `characters/heroine_smile.png` のような相対パス（オブジェクトキー）のみを保存**してください。
  - **推奨ディレクトリ／S3キー構成**:
    ```text
    {ASSET_ROOT}/
    └── projects/
        └── {projectId}/
            ├── bg/          # 背景画像 (bg_change.image)
            ├── characters/  # 立ち絵画像 (text.characterImage)
            ├── bgm/         # BGM音源 (bgm_play.bgmId)
            └── se/          # 効果音 (sound_effect.seId)
    ```
  - **ローカル開発から AWS (S3 + CloudFront) への移行方法**:
    - フロントエンドに環境変数 `NEXT_PUBLIC_ASSET_BASE_URL` を参照するヘルパー関数 `resolveAssetUrl(key)` を1つ用意します。
      - **ローカル開発時**: `frontend/public/assets/...`（またはバックエンドの静的配信）にファイルを置き、`NEXT_PUBLIC_ASSET_BASE_URL=/assets`
      - **AWS移行後**: S3バケット＋CloudFrontにファイルを置き、`NEXT_PUBLIC_ASSET_BASE_URL=https://xxxx.cloudfront.net`
    - この構成にしておけば、**AWS移行時にDB内の既存イベントデータを1件も書き換えることなく環境変数1つで切り替えが可能**になります。

## 3. アカウント作成・認証（メアド不要化＋管理者宛ワンタイムパス）
- **評価**: ⚖️ **方針は良いが、既存コードの `email` 依存箇所の整理と、より手軽な代替案の比較を推奨**
- **レビュー内容**:
  1. **既存コードとの兼ね合い（注意点）**:
     - 現在、`schema.prisma` の `User` モデルは `email` が `@unique` 必須となっており、**ログイン処理（`AuthService.login`）とプロジェクトへのメンバー招待（`ProjectService.inviteMember`）がどちらも `email` でユーザーを検索する実装**になっています。
     - メアド登録を廃止する場合、以下をあわせて変更する必要があります：
       - `User.name`（ユーザーネーム）に `@unique` 制約を付ける（`email` は削除または `String?` に変更）
       - ログインAPI・画面およびメンバー招待API・画面を「ユーザーネーム指定」に変更する
  2. **管理者メアド宛OTP vs 招待コード（合言葉）方式の比較**:
     - **ご提案の方式（管理者メアド宛にワンタイムパス送信）**:
       - セキュリティは高いですが、バックエンドにメール送信基盤（AWS SES / Resend / Nodemailer 等）の構築と、ワンタイムパスの有効期限管理テーブル（またはメモリ保持）の実装が必要です。
     - **代替案（環境変数による「招待コード／承認パスフレーズ」方式）**:
       - バックエンドの `.env` に `INVITE_CODE=xxxx` を設定し、隠し登録URLの画面で「ユーザー名・パスワード・招待コード」を入力させる方式（または管理者がダッシュボード上でワンタイム招待コードを発行してDiscord/LINE等で渡す方式）。
       - **メリット**: メール送信サーバーを用意しなくても**同じセキュリティ強度（管理者が許可した仲間しか登録できない）をはるかに少ない実装コストで実現**できます。メールサーバーを導入する前の段階ではこちらが特におすすめです。

## レビュー・設計方針

### 1. プロジェクト単位（`/projects/[projectId]/assets`）での管理方針について
- **評価**: ⭕ **データ構造・運用フローともに最適です**
- **理由**:
  - キャラクター名や立ち絵・背景・BGMは、1つのシナリオ（第1話）だけでなくプロジェクト内の全シナリオ（第1話〜最終話）で共通して使い回すものです。
  - そのため、`/projects/[projectId]` 配下にアセット・プリセット管理ページを設け、プロジェクト単位で一元管理する設計は無駄がなく、Step 2 で構築した `public/assets/projects/{projectId}/...` のディレクトリ構造とも完全に一致します。

### 2. データ保存方式の設計（どのようにプリセットとアセットを保持するか）

先日の `Event.data (Json)` の設計と同様に、**将来の拡張時にDBマイグレーションが不要になる設計**を推奨します。

#### 2.1 プリセット情報（キャラ名・アセット名リスト）の保存先
- **`Project` テーブルに `presets Json @default("{}")` カラムを追加する方式（推奨）**
  - `schema.prisma` の `Project` モデルに `presets Json @default("{}")` を1つ追加します。
  - フロントエンド側の型定義（`frontend/types/index.ts`）：
    ```ts
    export interface ProjectPresets {
      speakers?: string[];     // キャラ名プリセット (例: ["主人公", "ヒロイン", "先生"])
      characters?: string[];   // 立ち絵ファイル名一覧 (例: ["heroine_smile.png", "heroine_angry.png"])
      backgrounds?: string[];  // 背景ファイル名一覧 (例: ["classroom_day.png", "sunset.png"])
      bgm?: string[];          // BGMファイル名一覧 (例: ["bgm_daily.mp3"])
      se?: string[];           // SEファイル名一覧 (例: ["se_chime.wav"])
    }
    ```
  - **メリット**:
    - 将来「キャラ名と立ち絵グループを紐付けたい（例：話者で『ヒロイン』を選んだら、立ち絵プルダウンにヒロインの差分だけを優先表示する）」といったデータ構造の進化も、**フロントエンドの型変更だけで対応可能**になります。

#### 2.2 アセット追加の方法（ファイルアップロード ＋ ディレクトリ同期）
新規ページ `/projects/[projectId]/assets` での「アセットの追加」には以下の2通りがあり、**両方組み合わせる構成**が最も便利です。

1. **ブラウザからのファイルアップロード（推奨）**
   - `/projects/11/assets` 画面で画像・音源ファイルを選択（またはドラッグ＆ドロップ）すると、Next.js の API Route（またはバックエンド）経由で `frontend/public/assets/projects/11/{category}/` に実ファイルを保存し、同時に `presets` のリストへファイル名を自動追加します。
   - **AWS移行時**: アップロード先の処理をローカルファイル書き込みから「S3 Presigned URL（署名付きURL）へのPUT」に差し替えるだけで、UIやDB構造を一切変えずに移行できます。
2. **ファイル名の手動プリセット登録 ＆ 既存ディレクトリのスキャン**
   - すでに `public/assets/projects/11/` フォルダに直接置いたファイルや、まだ実ファイルはないが先にシナリオだけ書きたい場合の「仮ファイル名（例: `boss_battle_bg.png`）」もテキスト入力でプリセット一覧に追加できるようにします。

### 3. 各画面のUI・動線設計

#### ① 導線（リンクの配置場所）
1. **プロジェクト詳細ページ (`/projects/[projectId]`)**:
   - `ProjectHeader.tsx` の右上アクション領域（「プロジェクト削除」ボタンの左隣）に **`🎨 アセット・プリセット管理` ボタン** を追加し、`/projects/[projectId]/assets` へ遷移できるようにします。
2. **シナリオ編集ページ (`/projects/[projectId]/scenarios/[scenarioId]`)**:
   - シナリオヘッダーのボタン群にも **`🎨 アセット管理`** リンクを配置しておくと、執筆中に「新しいキャラ名や立ち絵を追加したい」と思った際に1クリックで移動できて便利です。

#### ② アセット・プリセット管理ページ (`/projects/[projectId]/assets`)
- **左カラム（または上部）：👤 キャラクター名（話者）プリセット**
  - 名前を入力して「＋追加」するだけで登録でき、タグ形式で一覧表示・削除が可能。
- **右カラム（または下部）：🖼️ カテゴリ別アセット管理（タブ切替）**
  - `🎭 立ち絵 (characters)` / `🖼️ 背景 (bg)` / `🎵 BGM (bgm)` / `🔊 効果音 (se)` の4タブ。
  - ファイルアップロード枠 ＋ ファイル名直接登録枠。
  - 登録済みアセットの一覧（立ち絵・背景は実際の画像サムネイルを表示し、ファイル未配置の場合は「未配置」バッジを表示）。

#### ③ シナリオ編集ページ (`/projects/[projectId]/scenarios/[scenarioId]`) のプルダウン入力
- `EventForm.tsx`（新規追加）と `EventEditModal.tsx`（編集モーダル）の両方で、以下の入力欄をプルダウン対応にします：
  | イベント種別 | 対象フィールド | プルダウンの選択肢 |
  | :--- | :--- | :--- |
  | `text` | `speaker` (話者名) | `presets.speakers` の一覧 ＋ `（話者なし / 地の文）` |
  | `text` | `positions[pos1..7]` (立ち絵) | `presets.characters` の一覧 ＋ `（前の状態を維持）` ＋ `🚫 退場 (none)` |
  | `bg_change` | `image` (背景) | `presets.backgrounds` の一覧 ＋ 標準キーワード（`classroom`, `sunset`, `night` 等） |
  | `bgm_play` | `bgmId` (BGM) | `presets.bgm` の一覧 |
  | `sound_effect` | `seId` (効果音) | `presets.se` の一覧 |

- **💡 運用上の重要工夫：「プルダウン選択」と「自由手入力」の併用**
  - シナリオ執筆中、1回だけ登場するモブキャラ（例: `村人A`）や一時的な仮ファイル名をわざわざアセット管理ページに戻って登録するのは手間になります。
  - そのため、**基本はプルダウン（`<select>`）で快適に選べつつ、「＋ 直接入力する」切替（またはカスタム入力モード）で自由な文字列も入力できるUI** にしておくと、プリセットの便利さと自由度の高さを両立できます。

## Step 3: アセット（立ち絵・背景・BGM・効果音）＆キャラクター名プリセット管理・プルダウン入力の実装
- **決定した仕様**:
  - プロジェクト詳細ページ（`/projects/[projectId]`）およびシナリオ編集ページ（`/projects/[projectId]/scenarios/[scenarioId]`）から、新設の **アセット・プリセット管理ページ（`/projects/[projectId]/assets`）** へ遷移可能にする。
  - アセット・プリセット管理ページでは、**キャラクター名（`speaker`）のプリセット登録・削除** と、**カテゴリ別アセット（`characters`, `bg`, `bgm`, `se`）の実ファイルアップロード・ファイル名先行プリセット登録・サムネイル／試聴確認・削除** を行えるようにする。
  - シナリオ編集ページ（新規追加フォームおよび編集モーダル）では、登録済みプリセットと配置済み実ファイルを自動統合した **プルダウン選択（`<select>`）** を標準提供し、ワンクリックで **自由テキスト直接入力（`<input>`）** にも切り替えられるようにする。
- **作成・変更したファイルと実装結果**:
  1. **バックエンド（DBスキーマ・DTO・Serviceの拡張）**:
     - `backend/prisma/schema.prisma`: `Project` モデルに `presets Json @default("{}")` カラムを追加。
     - `backend/src/project/dto/update-project.dto.ts` & `backend/src/project/project.service.ts`: `PATCH /projects/:id` でプロジェクト名だけでなく `presets` オブジェクトも更新・保存できるように拡張。
  2. **ローカルアセット走査・アップロード・プリセット保存 API Route**:
     - `frontend/app/api/projects/[projectId]/assets/route.ts`（新規作成）:
       - `GET`: `frontend/public/assets/projects/{projectId}/{characters,bg,bgm,se}` 配下の実ファイル一覧を自動スキャンし、同階層に保存された `presets.json` とあわせて返却。
       - `POST`: `multipart/form-data` で受け取った画像・音源ファイルを該当カテゴリディレクトリへ安全に保存（ファイル名サニタイズ済）。
       - `PUT`: キャラクター名やファイル名プリセットを `presets.json` に保存（DBの `Project.presets` とハイブリッド同期するため、Dockerコンテナ側でDBマイグレーションを実行する前でも即座に動作）。
       - `DELETE`: 指定された実ファイルをディレクトリから削除。
  3. **フロントエンド型定義・APIクライアントの拡張**:
     - `frontend/types/index.ts`: `ProjectPresets` 型および `ProjectAssetsResponse` 型を追加し、`Project` インターフェースに `presets?: ProjectPresets` を追加。
     - `frontend/lib/api.ts`: `getProjectAssets`, `saveProjectPresets`, `uploadProjectAssetFile`, `deleteProjectAssetFile` を実装。
  4. **アセット・プリセット管理ページの新規作成**:
     - `frontend/app/projects/[projectId]/assets/page.tsx`（新規作成）:
       - **キャラクター名（話者）プリセット管理セクション**: 話者名の追加・タグ一覧表示・個別削除UIを実装。
       - **カテゴリ別アセット管理セクション**: `立ち絵 (characters)` / `背景画像 (bg)` / `BGM (bgm)` / `効果音 (se)` の4タブ切り替え、複数ファイル対応のアップロード機能、実ファイル未配置時の「ファイル名のみ候補追加」機能、画像サムネイル表示（`resolveAssetUrl` 使用）・`<audio>` 試聴プレイヤー、「実ファイル有」「プリセット登録」のステータスバッジ表示を実装。
  5. **各画面間のナビゲーションリンク追加**:
     - `frontend/components/ProjectHeader.tsx`: プロジェクト詳細画面ヘッダーに `🎨 アセット・プリセット管理` ボタンを追加。
     - `frontend/app/projects/[projectId]/scenarios/[scenarioId]/page.tsx`: シナリオ編集画面ヘッダーおよびイベント追加フォーム右上に `🎨 アセット・プリセット管理`（`🎨 アセット・キャラ名追加`）リンクを追加し、`getProjectAssets` で取得した候補一覧を子コンポーネントへ供給。
  6. **シナリオ編集画面でのプルダウン選択＋直接入力切替UIの実装**:
     - `frontend/components/EventForm.tsx`, `frontend/components/EventEditModal.tsx`, `frontend/components/EventTimeline.tsx`:
       - `text` の `speaker`（話者名）、`text` の `positions[pos1..pos7]`（7スロット立ち絵）、`bg_change` の `image`（背景画像）、`bgm_play` の `bgmId`（BGM）、`sound_effect` の `seId`（効果音）の5箇所すべてに `<select>` プルダウンを導入。
       - 各入力欄のラベル横に `✏️ 直接入力` / `📋 プルダウン選択` のトグルボタンを設け、プリセット外の値も柔軟に入力でき、かつ既存の直接入力値もプルダウン選択肢内に自動保持される安全なUIを実現。
