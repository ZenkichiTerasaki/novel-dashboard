## 2. 案1（AWS EC2 + Docker + GitHub Actions）の詳細構成

### 【インフラ要素】
* **サーバー**: AWS EC2 (`t4g.small` ARMベース / Ubuntu Server)
* **ドメイン & SSL**: Route 53 (または任意ドメイン取得サービス) + Nginx + Certbot (Let's Encrypt による無料HTTPS化)
* **コンテナ実行環境**: Docker & Docker Compose (Frontend: Next.js / Backend: NestJS / DB: PostgreSQL)

## 3. CI/CD パイプライン構成案 (GitHub Actions)

### 【パイプラインの全体フロー】

```mermaid
flowchart LR
    A[💻 開発者\ngit push] --> B[⚙️ GitHub Actions]
    
    subgraph CI [1. CI (継続的インテグレーション)]
        B --> C[🧪 テスト実行\n(npm test)]
        C --> D[🔍 Lint / 型チェック\n(eslint, tsc)]
    end

    subgraph CD [2. CD (継続的デプロイ)]
        D --> E[📦 Dockerイメージ構築 & Push\n(Docker Hub / AWS ECR)]
        E --> F[🚀 EC2へSSH接続 & 再起動\n(docker compose pull && up)]
    end

    F --> G[🌐 本番Webサイト更新]
```

### 【実現方式の比較】

#### パターンA：実務標準スタイル（推奨・就活アピール度：★★★★★）
1. **CI**: Pull Request 作成時または `main` 押し込み時に GitHub Actions 上で Jest テストおよび Lint を実行。
2. **Build**: GitHub Actions で Docker イメージを自動ビルドし、Docker Hub や AWS ECR (Elastic Container Registry) に Push。
3. **CD**: SSH アクション経由で EC2 に接続し、`docker compose pull && docker compose up -d` を実行してコンテナを更新。

#### パターンB：シンプル直結スタイル（手軽さ優先：★★★★★）
1. **CI**: GitHub Actions 上でテストと Lint を実行。
2. **CD**: SSH アクション (`appleboy/ssh-action`) を使用して EC2 内で直接 `git pull` および `docker compose up -d --build` を実行。
